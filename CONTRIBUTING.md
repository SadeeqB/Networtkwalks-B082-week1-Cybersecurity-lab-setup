# Contributing

Thanks for your interest in improving this project! Contributions are welcome — below are simple guidelines to help your change be accepted quickly.

1. Filing an issue
- Please open an issue to discuss significant changes, missing content, or bugs before sending a PR. Include a clear description and steps to reproduce if applicable.

2. Pull requests
- Fork the repository and create a branch with a descriptive name, e.g., `fix/readme-typo` or `feat/add-license`.
- Keep changes focused and small; one logical change per PR is easier to review.
- Rebase or merge the latest main branch before opening a PR to avoid conflicts.
- Write clear commit messages. Use present-tense, e.g., "Fix typo in README".

3. Code style and content
- This repository mainly contains documentation. Keep content clear, concise, and reproducible.
- For commands, prefer using `bash`/CLI examples where appropriate.

4. Tests
- If you add scripts or automation, include instructions and any test steps.

5. Review process
- PRs will be reviewed by the repository owner or maintainers. They may request changes; please address review comments promptly.

6. License
- By contributing, you agree that your contributions will be licensed under the project's MIT License.

If you're unsure where to start, open an issue and we can point you to good first contributions.
